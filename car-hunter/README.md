# car-hunter

엔카(encar.com) 중고 전기차 매물을 수집해 가성비 점수를 매기고,
헤이딜러 '숨은이력찾기' 결과를 병합해 최종 순위 리포트를 만드는 개인 검토용 도구.

**대상 차종**
- BMW iX xDrive50 (2022~2024년식)
- 벤츠 EQE SUV 350 4MATIC (2023~2024년식)

대상 차종·연식·점수 가중치는 전부 `config.py` 에서 바꾼다.

---

## 설치

```bash
pip install -r requirements.txt
```

## 전체 흐름

```
collect.py  ─→  data/listings.csv , data/details.json
score.py    ─→  data/scored.csv  , report.html (1차)
                  ↓  상위 10대 차량번호를 헤이딜러 앱에서 수동 조회
                  ↓  결과 스크린샷을 hidden/ 에 저장
merge.py    ─→  data/merged.csv  , report.html (최종)
```

세 단계는 서로 독립적으로 실행할 수 있다. 각 단계는 파일로만 소통한다.

## 1단계 — 수집 (`collect.py`)

**파서를 믿기 전에 실제 응답부터 확인할 것.**

```bash
python collect.py --probe
```

`--probe` 는 11가지를 실제로 두들겨 보고 결과를 보고한다:

1. `/premium` · `/general` 중 어느 엔드포인트가 살아 있는지
2. 실제 요청 URL (브라우저 주소창에 붙여넣어 대조 가능)
3. 응답 최상위 구조
4. 결과 1건의 전체 필드
5. 필드 매핑 결과 — 실패한 필드에 `<-- 매핑 실패` 표시
   (`trim_detail` 처럼 없어도 정상인 항목은 `(선택 항목)` 으로 구분)
6. **어떤 조건이 매물을 걸러내는지** — 연식 / Hidden / CarType / AdType /
   하위 Model 을 하나씩 빼며 총건수를 비교하고, `CarType` 반대값도 시험한다
7. **연식 필터가 실제로 먹는지** (필터 유/무 총건수와 반환 연식 범위 비교)
8. **페이징이 실제로 먹는지** (1·2페이지 ID 중복 여부)
9. 첫 매물의 **상세 API 4종** (차량번호/옵션, 사고이력, 성능점검, 엔카진단)
10. **옵션 배열 탐색** — 상세 응답 안의 모든 배열을 경로·길이·타입·샘플과
    함께 나열하고, 옵션명 배열 / 옵션 코드 배열 / 코드→이름 변환표를 구분해
    표시한다. 상세 응답 전체는 `data/raw_detail.json` 에 저장된다
11. 최종 파싱 결과 (차량번호, 옵션 수, 에어서스 판별 상태 등)

### 옵션 코드 변환표를 직접 채우기

변환표 API 를 못 찾았다면 `data/option_codes.json` 을 직접 만들면 된다.
수집 시 이 파일이 있으면 API 보다 우선 사용한다.

```json
{
  "005": "에어서스펜션",
  "007": "인테그럴 액티브 스티어링",
  "002": "통풍시트"
}
```

에어서스 관련 코드 몇 개만 채워도 판별은 된다. 전부 채울 필요 없다.

### 옵션이 숫자 코드로 오는 경우

엔카는 옵션을 이름이 아니라 숫자 코드 배열(`options.standard: [1, 7, 23]`)로
내려주기도 한다. 이러면 키워드 매칭으로 에어서스를 판별할 수 없다.

이 도구는 그 상황을 **"없음" 으로 뭉개지 않고 `판별불가` 로 표시**하고,
옵션 코드→이름 변환표를 자동으로 찾아 적용한다 (`--probe` 의 [10] 이
변환표 위치를 시험한다). 변환표를 찾으면 수집 시 1회만 받아 전 매물에
적용하므로 추가 요청 부담이 없다.

### 제조사·모델 표기 확인

엔카 내부 표기는 브랜드마다 다르다 (BMW 는 `BMW`, 벤츠는 한글일 가능성).
결과가 0건이면 아래로 실제 표기를 확인한다:

```bash
python collect.py --discover                    # 제조사 목록
python collect.py --discover --mfr 벤츠          # 그 제조사의 모델그룹
python collect.py --discover --mfr 벤츠 --mg EQE  # 하위 모델
```

확인한 값을 `config.py` 의 `TARGETS` 에 넣으면 된다.
브라우저에서 복사한 q 를 그대로 쓰려면 `--q '<q값>'`.

### 검색 쿼리 구조 (2026-08 실측)

```
(And.
  (And.Hidden.N._.MultiViewHidden.N._.Year.range(202200..202412)._.
    (C.CarType.N._.
      (C.Manufacturer.BMW._.ModelGroup.iX.)))
  _.(Or.AdType.B._.MultiViewAdType.B.))
```

`sr` 은 `|정렬키|오프셋|개수` 형식 (`|ModifiedDate|0|20`).
`/premium` 은 `AdType.B`, `/general` 은 `AdType.A` 매물을 돌려주므로
기본값은 **둘 다 수집해 `vehicle_id` 로 중복 제거**한다. 한쪽만 쓰면
시세 회귀 표본이 광고 상품 쪽으로 치우친다.

확인이 끝나면 본 수집:

```bash
python collect.py                # 전체
python collect.py --limit 20     # 모델당 20건
python collect.py --no-detail    # 검색 결과만 (빠른 점검, 차량번호 없음)
```

수집 항목: 차량번호 · 가격 · 연식(년/월) · 주행거리 · 지역 · 트림 · 옵션 목록 ·
사고이력 · 엔카진단 여부 · 성능점검 요약 · 매물 URL ·
**신차가(originPrice)** · 보증정보 · 조회수 · 찜수 · 엔카진단 플래그
(`encarCheck` / `directInspected`).

신차가가 있으면 **신차가 대비 감가율**을 계산해 리포트에 함께 표시한다.

**요청 정책** — 간격 3초, 재시도 2회(네트워크 오류·5xx 에만), User-Agent 포함.
`config.COLLECT` 에서 조정하되 간격은 줄이지 말 것.

**검색은 전량, 상세는 상위 N 대만.** 검색 결과(가격/연식/주행거리)는 한 번에
100건씩 오므로 400건이라도 요청 4번이면 끝나고, 시세 회귀에는 전량이 필요하다.
반면 상세는 매물당 4회 요청이라 400건 전량이면 40분을 넘긴다. 그래서 검색
결과만으로 매길 수 있는 1차 점수(시세 잔차 + 배터리 잔여)로 상위
`detail_top_n`(기본 50) 대만 상세를 받는다.

- 상세를 받은 매물만 최종 **순위** 대상이 된다 (차량번호·옵션·사고이력이 있어야
  제대로 된 점수가 나오므로).
- 나머지는 **시세 회귀 표본**으로 쓰인다. `detail_fetched` 컬럼으로 구분된다.

**제외 조건** — 트림 불일치(`badge_excludes`: iX 의 `M70`/`xDrive40` 등),
리스·렌트·영업용 매물(`EXCLUDE_SELL_TYPES`), 연식 범위 밖. `--probe` 가
어떤 매물이 왜 걸러졌는지 이유와 함께 보여준다.

**AdType 조건은 기본으로 끈다.** 실측에서 이 조건 하나가 매물을 2건까지
줄였다 (제거 시 28건). 광고 상품 여부는 매물 품질과 무관하다.

**차단 감지** — HTTP 429/403/401, 캡차 문구, JSON 아닌 응답 중 하나라도 나오면
**재시도 없이 즉시 중단**하고 `data/BLOCKED.txt` 에 어느 단계에서 막혔는지 기록한다.
그때까지 확보한 매물은 버리지 않고 저장한다.

**엔카의 차단과 '도달 불가'는 구분한다.** 프록시 정책 거부·방화벽·DNS 실패처럼
엔카 서버에 닿지도 못한 경우는 재시도가 무의미하므로 즉시 멈추고, 원인과 확인할
항목을 안내한다. 이때는 `BLOCKED.txt` 를 남기지 않는다 (엔카가 막은 게 아니므로).

| 종료 코드 | 의미 |
|---|---|
| `0` | 정상 |
| `1` | 수집 0건, 또는 그 밖의 오류 |
| `2` | **엔카 차단** (429/403/캡차) — `data/BLOCKED.txt` 참조 |
| `3` | **도달 불가** (프록시/방화벽/DNS) — 네트워크 경로 문제 |

### 네트워크 없이 점검하기

```bash
python samples/make_fixture.py       # 합성 샘플 생성
python collect.py --fixture samples/ # 2·3단계 파이프라인 점검용
```

`--probe` / `--discover` 자체를 점검하려면 엔카 응답을 흉내내는 로컬
가짜 서버를 띄울 수 있다 (`samples/fake_encar_server.py`).

## 2단계 — 가성비 스코어링 (`score.py`)

```bash
python score.py            # 기본 상위 10대
python score.py --top 15
```

점수 구성 (`config.SCORING`):

| 항목 | 배점 | 산출 |
|---|---|---|
| 시세 잔차 | 0~40 | 모델별 `가격 ~ (경과연수, 주행거리)` 최소제곱 회귀의 예측가 대비 저평가 정도 |
| 배터리 보증 잔여 | 0~20 | 최초등록 기준 **8년 / 16만km 중 먼저 도달하는 쪽** 의 잔여 비율 |
| 가점 | + | 무사고 +8 · 엔카진단 +5 · 1인소유 +4 · 에어서스 옵션 키워드 +6 |
| 감점 | − | 연 2.5만km 초과 −6 / 3만km 초과 −12 · 침수·전손 −40 · 렌트·영업용 −10 |

- 표본이 5건 미만이면 회귀 대신 중앙값 비교로 후퇴하고 `신뢰도 낮음` 을 표시한다.
- 콘솔에 모델별 시세 요약(최저/중앙/최고, 회귀식, R², 잔차 표준편차)과
  상위 매물을 출력하며, **차량번호를 `【 】` 로 강조**한다.

## 3단계 — 헤이딜러 숨은이력 병합 (`merge.py`)

외부 OCR·비전 API를 쓰지 않는다. 이미지 판독은 **클로드 코드가 세션 안에서
직접** 수행하므로 추가 비용이 없다.

```bash
# 1) 조회할 차량번호 목록
python merge.py --list

# 2) 헤이딜러 앱 '숨은이력찾기'에서 각 번호를 수동 조회하고
#    결과 화면 스크린샷을 hidden/ 에 저장
#    파일명에 차량번호를 넣으면 자동 매칭된다: hidden/112다2644.png

# 3) 이미지 목록과 판독 요청문 출력
python merge.py --show

#    → 이 출력을 클로드 코드에 주면 클로드가 이미지를 읽어
#      hidden/extracted.json 을 생성한다

# 4) 병합 + 최종 점수 재계산 + 리포트
python merge.py --apply
```

`hidden/extracted.json` 형식 (`hidden/extracted.template.json` 참고):

```json
{
  "records": [
    {
      "plate_no": "112다2644",
      "source_image": "hidden/112다2644.png",
      "battery_maker": "삼성SDI",
      "airsus": true,
      "insurance_repair_won": 0,
      "insurance_summary": "내차 0건 / 상대차 0건",
      "notes": "출고옵션에 에어서스펜션 포함 확인"
    }
  ]
}
```

`airsus` 는 `true` / `false` / `null`(화면에서 판단 불가) 세 가지를 구분한다.

**재계산 가감점** (`config.py`):

| 항목 | 조정 |
|---|---|
| 배터리 삼성SDI | +8 |
| 배터리 LG·SK온 | +2 |
| 배터리 CATL | 0 |
| 배터리 파라시스 | **−25** |
| 에어서스 장착 확정 | +8 |
| 에어서스 미장착 확정 | −4, 그리고 1차 키워드 추정 가점(+6) 회수 |
| 보험 수리이력 | 0원 +5 / ~50만 −2 / ~200만 −6 / ~500만 −14 / 500만 초과 −25 |

## 최종 출력 — `report.html`

외부 CDN 없이 자체 완결된 단일 HTML (인라인 SVG 차트, 다크모드 대응).

- 모델별 시세 분포 산점도 + 회귀 시세선 (파랑=저평가, 빨강=고평가)
- 최종 순위표: 차량번호 강조, 가격 vs 예측가, 연평균 주행, 배터리 보증 잔여,
  매물·사진 링크, 매물별 추천/주의 사유
- **계약 전 수동 확인 항목** 체크리스트 (SOH 진단, 에어서스 실차 확인, 하부 점검 등)

## 파일 구성

| 파일 | 역할 |
|---|---|
| `config.py` | 대상 차종, 요청 정책, 점수 가중치 — 튜닝은 여기서만 |
| `common.py` | 경로·로깅·CSV/JSON·숫자/날짜 유틸 |
| `encar_api.py` | 엔카 엔드포인트, 방어적 파서, 차단 감지 |

| `scoring.py` | 점수 계산 코어 (2·3단계 공용) |

| `merge.py` | 3단계 |
| `report.py` | report.html 생성 |
| `samples/` | 오프라인 점검용 합성 데이터 생성기 |

## 주의

- 개인 검토용 **소량 수집** 전용이다. 요청 간격을 줄이거나 병렬화하지 말 것.
- 차단이 감지되면 즉시 멈춘다. 우회를 시도하지 않는다.
- 점수는 공개 매물 정보에 기반한 **상대 비교**일 뿐 차량의 실제 상태를
  보증하지 않는다. 계약 전 리포트의 체크리스트를 직접 확인할 것.
- `hidden/` 의 스크린샷과 `data/` 산출물은 개인 차량 정보이므로
  `.gitignore` 로 제외되어 있다.
